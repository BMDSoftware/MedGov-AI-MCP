Estive a mexer no mcp-radlex, a implementação que estava era toda local, ou seja, o servidor estava a ler os templates do disco, e a responder a queries com base nesses templates. Estava bastante limitado.
Para ter acesso a mais templates, e mais especificos, implementei o mcp que acede a API do radReport.
Agora o mcp-radlex tem acesso a todos os templates do radReport, e pode responder a queries com base nesses templates.

API radreport: https://radreport.org/developers

Tem as seguintes tools disponiveis:

- list_subspecialties: devolve o catálogo de subespecialidades suportadas (ex.: CH, NR, AB), para saber os domínios existentes antes de procurar templates.
- find_templates: pesquisa templates por subespecialidade (specialty_code) e opcionalmente por query textual (ex.: parte do título), retornando uma lista com template_id + metadados.
- get_template_schema: dado um template_id, retorna as secções/campos do template (html_id, label, type, options), isto é, o “contrato” do que pode/precisa ser preenchido.
- generate_report: gera o relatório final (texto + HTML) a partir de um template_id e de um dicionário findings no formato { html_id: valor }, validando selects contra as options do schema.
